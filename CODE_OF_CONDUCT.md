# Code of Conduct

## Our Commitment

ReleaseGuard is a developer-focused project intended to encourage constructive collaboration around software quality, release engineering, automation, and responsible AI-assisted development.

We are committed to providing a welcoming, respectful, and harassment-free environment for everyone who participates in the project, regardless of background, experience level, identity, or role.

## Expected Behavior

Contributors and participants are expected to:

- Be respectful, constructive, and professional.
- Assume good intent while remaining open to feedback.
- Focus discussions on code, architecture, evidence, documentation, and project goals.
- Provide clear technical reasoning when proposing changes.
- Accept constructive criticism gracefully.
- Respect project scope, maintainer decisions, and agreed technical constraints.
- Protect confidential information, credentials, and private repository contents.
- Clearly distinguish verified results from assumptions, experiments, and future plans.
- Treat AI-generated suggestions as proposals that require human review and validation.

## Unacceptable Behavior

The following behavior is not acceptable:

- Harassment, discrimination, threats, intimidation, or personal attacks.
- Deliberate disclosure of private or confidential information.
- Publishing or committing real credentials, tokens, secrets, or private repository data.
- Malicious code, intentionally destructive changes, or unauthorized access attempts.
- Misrepresenting an AI-generated result as a verified build, test, security result, or deployment outcome.
- Spam, trolling, or repeated disruptive behavior.
- Any conduct that would make a reasonable contributor feel unsafe or unwelcome.

## Technical and AI-Assisted Contributions

ReleaseGuard may use AI-assisted development and repository analysis. Contributors should:

1. Review AI-generated code before committing it.
2. Validate behavior with appropriate tests and checks.
3. Avoid introducing unsupported security or performance claims.
4. Never expose secrets to AI services unnecessarily.
5. Document meaningful assumptions or limitations in pull requests.

## Enforcement

Maintainers may remove, edit, or reject contributions that violate this Code of Conduct.

Depending on severity, enforcement may include:

- A private or public warning.
- Request for corrective action.
- Temporary restriction from project participation.
- Permanent removal from project participation.

## Reporting

For conduct concerns, please contact the repository maintainers privately rather than opening a public issue containing sensitive information.

For security vulnerabilities, use the process described in [`SECURITY.md`](SECURITY.md).

## Scope

This Code of Conduct applies to:

- Issues
- Pull requests
- Discussions
- Documentation contributions
- Project demonstrations
- Contributor communication related to ReleaseGuard

Thank you for helping make ReleaseGuard a constructive engineering project.
